# 技术笔记记法（术）

适用：工具使用方法、踩坑经验、调试方法、配置流程、工程实践。放 `术中自有万钟粟/` 下。

---

## 记什么

记的是**个人经验**，不是抄手册。值得记的东西只有三种：

1. **怎么用**：操作步骤、按钮/命令是什么、配置怎么改
2. **踩了什么坑**：事故经过、原因分析、正确做法
3. **选型判断**：同类工具/方案怎么选，为什么

如果官方文档已经写得很清楚的东西，不要搬运。只记你自己操作过、验证过、踩过坑的内容。

## 记多少

- **深度标准**：讲到"能上手操作"就停
- 不追求体系化，不要求覆盖所有功能
- 一张图 + 几行操作说明，比长篇文字好

## 怎么记

### 开篇

```
# <技术/工具名>

[← 返回 MOC](MOC.md) | [← 主页](../index.md)

> **一句话**：这个东西是什么 / 用来做什么。

---
```

### 正文风格

- **步骤化**。按钮叫什么、旋钮往哪拧、命令怎么敲，直接写
- **图片辅助**。面板照片、接线图、截图，比文字直观
- **踩坑是核心价值**。格式：日期 + 事故经过 + 原因 + 教训
  ```
  ## 注意细节

  26/4/19
  今天用示波器的时候把芯片烧了，因为示波器的地不是浮空的...
  ```
- 外部链接（教程、参考视频、网盘）放在正文里

### 收尾

```
---
```

技术笔记不需要"如果你正在跟随梳理"那种学习导向的结尾。
