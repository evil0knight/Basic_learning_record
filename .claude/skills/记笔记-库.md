# 模块器件笔记记法（库）

适用：硬件模块、芯片、器件、PCB 电路、外设驱动程序。放 `库中车马多如簇/<模块名>/` 下。

每个模块建一个**子文件夹**，里面有两种文件：**MOC.md**（原理索引）和**程序文件**（写法代码）。

---

## MOC.md — 原理与入口

### 记什么

模块的基础原理：是什么、怎么工作、关键参数、分类对比。不写具体代码。

### 记多少

- 用**表格**做索引，不用大段文字
- 每行：主题 | 简介 | 笔记链接 | 相关原理（交叉引用回"书"）

### 格式

```
# <模块名> — 知识地图

[← 返回上级 MOC](../MOC.md) | [← 主页](../../index.md)

> 一句话说明这个模块是什么

---

### 🔴分类名

| 主题 | 简介 | 笔记 | 相关原理 |
| ---- | ---- | ---- | -------- |
| ...  | ...  | ...  | ...      |
```

章节标题用 `### 🔴标题`，**不使用 `<details>` 折叠**。

顶部导航如果模块有对应的理论学科（比如 FreeRTOS → 操作系统），加上交叉引用链接。

---

## 程序文件 — 写法代码

### 记什么

同一种外设/模块的**多种写法**，每种写法完整可复制。每种写法是一个独立的 `##` 区块。

### 记多少

- 每种写法：2-3 句说明（适用场景） + 完整代码
- 代码按 `.h` / `.c` / `main` 用注释分隔
- **代码必须完整**：含变量声明、头文件引用、初始化逻辑

### 格式

```
# <模块名>程序

[← 返回 MOC](MOC.md) | [← 主页](../index.md)

---

## 配置问题（可选但推荐）

在选择写法前，先问几个问题帮读者定位：

1. 需要几个 XXX？
2. 什么模式？
3. 是否需要 YYY 功能？

根据回答自动推荐写法。

---

## 🔴写法名称（一句话适用场景）

2-3句说明为什么用这种写法、适合什么情况。

```c
// ── xxx.h ────────────────────────────────────────
// 头文件内容

// ── xxx.c ────────────────────────────────────────
// 源文件内容

// ── main.c 使用示例 ─────────────────────────────
// 调用示例
```

---

## 🔴写法名称2（一句话适用场景）

...
```

### 程序文件规则

1. 每种写法标题：`## 🔴写法名称（适用场景）`
2. 代码块用 ` ```c ` 或 ` ```cpp ` 标注语言
3. 代码能**直接复制使用**，不做省略
4. 平台相关函数名保留原样，由用户适配
5. `.h` / `.c` / `main` 用注释分隔线区分模块

### 同步索引

新增模块时按 CLAUDE.md 规则更新：
- `库中车马多如簇/MOC.md`（模块入口表格）
- `README.md`（模块库表格）
