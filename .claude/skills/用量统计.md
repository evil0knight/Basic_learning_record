# 用量统计

## 数据源

`%USERPROFILE%\.dsh\sessions\<项目目录>\session-xxx\session.jsonl.zstd`

每步的 `assistant/chunk` 事件里带 `usage`：

```json
{"inputTokens": 278, "outputTokens": 3609, "cacheReadTokens": 1024, "reasoningTokens": 1358}
```

日志是 zstd 压缩的 jsonl，需要 `pip install zstandard` 才能读。

## 用法

```powershell
python "D:\Basic_learning_record\.claude\scripts\usage.py" --budget 20
python "D:\Basic_learning_record\.claude\scripts\budget_guard.py"            # 单次检查
python "D:\Basic_learning_record\.claude\scripts\budget_guard.py" --watch    # 后台循环
```

单价和预算写在 `.claude/scripts/prices.json`，改一次就够。**必须按 https://api-docs.deepseek.com/quick_start/pricing 核对真实单价**，默认值只是占位。

注意：这些脚本只是「看清花了多少」，**不是硬限额**。真正的硬限额是 DeepSeek 的预付费余额，余额为 0 时 API 直接报错停止。

## 怎么读结果

| 字段 | 含义 |
| ---- | ---- |
| 未缓存输入 | 每次新进上下文的部分，通常很小 |
| **缓存读取** | 每步重发的历史上下文，**通常是花费大头** |
| 输出 | 我写出来的字，含推理 token |

## rules

- **花费的大头是缓存读取，不是输出。** 上下文越长，每步越贵，所以「多写文件」不是主要成本，「多来回」才是。
- 每写完一批就查一次，不要在不知道余额的情况下连续写。
- 单价必须按实际模型核对，默认值只是量级参考。
- 统计只覆盖当前会话；跨会话的总账要把多个 session 文件分别跑。
