# 学科知识笔记记法（书）

适用：教材理论、概念原理、机制算法。放 `书中自有黄金屋/<学科>/` 下。

---

## 记什么

记的是**理解**，不是罗列知识点。每一段内容都要回答三个问题：

1. 这个概念/机制**要解决什么问题**？
2. 它**怎么解决的**？
3. 它有什么**局限**？（引向下一个改进机制）

## 记多少

- **深度标准**：讲到"为什么这样设计"，不是"有哪些特性"
- 如果一个概念有演进历史（比如互斥：单标志 → 双标志 → Peterson → TSL → 信号量），**必须串成演进线**，每种讲三件事：思想、优点、缺陷
- 概念对比用表格，不要各写一大段

## 怎么记

### 开篇

```
# <主题名>

[← 返回 MOC](MOC.md) | [← 主页](../../index.md)

> 一句话场景引导（可选）

---

一句话定性，讲清楚"这一章本质上在处理什么问题"
```

### 正文风格

- **口语化、场景化**。用"你可以这样理解"、"也就是"、"所以"这类连接词
- **善用类比**。抽象概念要翻译成人话："两个冤家不能见面"（互斥）、"里面有人了，后来的等"（忙则等待）
- **从问题出发**。不要平铺"X 有以下几个特性"，要写"为什么需要 X？因为 Y 有问题"
- **概念对比用表格**，一目了然
- 小节标题用 `##` 和 `###`，不要用 `<details>` 折叠
- 数学公式用 `$...$` / `$$...$$`

### 交叉引用

每个理论点尽量引用到实际的实现：
- OS 理论 → 链接到库里的 FreeRTOS 笔记
- 网络协议 → 链接到库里的具体模块（UART、CAN）
- 数据结构 → 链接到 C 语言实现

交叉引用写在正文里，不是单独开一节。

### 收尾

```
---

如果你正在跟随梳理, 返回 [MOC←](MOC.md)
```

**不要写"一句话总结"和"本章小结"**，正文讲完直接收束。
