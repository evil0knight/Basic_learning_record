# 记笔记

用户说"记笔记"时，先不急着写。做两件事：

## 第一步：判断这东西属于哪个区

| 区 | 判断标准 | 典型例子 |
|---|---|---|
| **书** | 教材/理论概念、原理、机制 | "我刚学了 TCP 拥塞控制"、"进程调度算法" |
| **术** | 工具使用、踩坑经验、调试方法、配置流程 | "今天用示波器烧了芯片"、"Git 怎么用" |
| **库** | 硬件模块、芯片、器件、电路、程序写法 | "LED 驱动怎么写"、"CAN 总线原理" |

如果用户说的东西跨区（比如既有理论又有硬件），按 CLAUDE.md 归档边界规则判断。原则：**只要主体是硬件/模块/电路，归库。**

## 第二步：分流到对应子 skill

判断清楚后，告诉用户你判断的结果，然后按对应子 skill 的记法来写：

| 区 | 对应 skill | 记法核心 |
|---|---|---|
| 书 | `/记笔记-书` | 问题驱动，把抽象翻译成人话 |
| 术 | `/记笔记-术` | 经验驱动，记录个人操作和踩坑 |
| 库 | `/记笔记-库` | 写法驱动，代码能直接复制使用 |

---

## 判断不清时

直接问用户："这个东西更偏向理论概念（书）、工具使用经验（术）、还是硬件模块代码（库）？"
