# 重组文件

## workflow

1. 先移动文件到指定位置,内容先不变
2. 查看源目录、目标目录和 Git 状态，确定“旧路径 → 新路径”，保留已有修改。
3. 用 `git mv` 移动已跟踪的正文和专属图片；未跟踪文件普通移动。共享图片先检查其他引用方。
4. 新建或更新目标 `MOC.md`，同步修改源 MOC 和受影响的上级入口。
5. 更新搬迁页面的顶部导航，按新位置计算相对路径。
6. 修复两个方向的引用：其他页面指向搬迁页面的链接，以及搬迁页面里的正文、图片和附件链接；标题变化时同步修复锚点。
7. 用 `rg`（与 `grep` 类似的文本搜索工具）在笔记和索引文件中分别搜索旧路径、文件名，不能只搜索被移动的文件夹。
   逐一确认命中内容是否指向被移动的文件，并改为相对于引用页面的新路径；修正后再次搜索，确认没有仍指向旧位置的链接。
8. 检查新链接目标与大小写，查看 Git 差异确认没有遗漏或误删。

## rules

- 只读取相关文件，不通读全库；不覆盖同名文件或改动无关内容。
- 文件及目录名不含括号，Markdown 扩展名使用小写 `.md`。
- 不自动提交或上传；完成后简要列出移动结果和检查结果。
