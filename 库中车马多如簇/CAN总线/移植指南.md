# CAN 移植与使用指南

## 1. 接口与配置边界

应用使用统一的 `core_can_*` 接口与 `st_can_frame_t`。同步/异步发送、FIFO 轮询和回调注册在两个后端上保持一致。

| 后端 | 编译宏 | 生成文件 | 支持的帧 |
| --- | --- | --- | --- |
| FDCAN，默认 | CORE_CAN_USE_FDCAN=1 | fdcan.h / fdcan.c，hfdcan1 | 经典 CAN、CAN FD、FD + BRS |
| bxCAN | CORE_CAN_USE_FDCAN=0 | can.h / can.c，hcan1 | 经典 CAN |

宏须在工程编译选项或 main.h 中统一设置，保证所有编译单元一致。bxCAN 硬件不能通过软件升级为 FD。

位时序、GPIO、NVIC、消息 RAM 和底层句柄初始化由 CubeMX 负责；平台接口负责参数校验、DLC 编解码、HAL 调用和中断分发，不绑定具体 MCU 型号。

## 2. 复制与编译

从 [工程代码索引](./03_Firmware/MOC.md) 选择一个版本：

| 版本 | 源文件 | 头文件搜索路径 |
| --- | --- | --- |
| 通用分层版 | can_port.c、user_isr_handlers.c | can/inc、app_isr_handlers、CubeMX Core/Inc |
| FOC简化版 | core_can.c | can/inc、CubeMX Core/Inc |

两版公开符号同名，不能同时编译。使用 C99 或更高标准，无 RTOS、动态分配或额外外部依赖。
HAL 弱回调覆盖模式使用 HAL 默认配置；若工程启用了 HAL 动态回调注册，须将这些转发函数注册到对应 HAL 句柄。

## 3. CubeMX 配置边界

FDCAN 后端由工程完成：

1. 选择支持 FD 的帧格式；使用 BRS 时启用 FD with Bit Rate Switching，并分别配置仲裁段和数据段位时序。
2. 配置标准/扩展过滤器数量。API 的 filter_bank 是所选 ID 类型内的过滤器索引，必须小于配置数量。
3. 配置 TX FIFO/Queue 和所需的 RX FIFO。可配置消息 RAM 的系列须将 TX、RX 元素数据区设为 64 字节，并为多实例分配互不重叠的区域；固定布局的系列使用 HAL 提供的布局。
4. 启用实际使用的 FDCAN 中断线，让生成的 IRQHandler 调用 HAL_FDCAN_IRQHandler。
5. 执行生成的 MX_FDCANx_Init，建立 hfdcan1 等句柄。使用支持目标数据速率的 CAN FD 收发器，并配置总线终端电阻。

bxCAN 后端保留原有 CubeMX 配置，执行 MX_CANx_Init，并通过 HAL_CAN_IRQHandler 转发 TX、RX0、RX1、错误中断。

## 4. 填通用版实例表

编辑 [can_port_config.h](./03_Firmware/通用分层版/04_platform/platform_mcu/can/inc/can_port_config.h)，删除零初始化占位项并启用：

```c
static const st_can_config_t g_can_configs[CORE_CAN_MAX] =
{
    [CORE_CAN1] =
    {
        .p_handle = &hfdcan1, /* bxCAN 后端使用 &hcan1。 */
        .timeout = CORE_CAN_TX_TIMEOUT_MS
    }
};
```

默认不绑定硬件，init 返回 CORE_CAN_ERR_NOT_READY。配置头文件只由 can_port.c 包含。
timeout 保存板级建议值；同步 API 使用显式传入的 timeout_ms，单位毫秒，0 表示无限等待。

增加第二路时，在 CORE_CAN_MAX 前增加 CORE_CAN2，并在表中绑定 hfdcan2 或 hcan2。业务 API 只需更换 instance 参数。

## 5. 帧结构与长度

| 字段 | 含义 |
| --- | --- |
| id | 右对齐的 11 位标准 ID 或 29 位扩展 ID |
| is_ext | 0 标准帧，1 扩展帧 |
| is_fd | 0 经典 CAN，1 CAN FD |
| is_brs | 仅 FD 帧可为 1，表示数据段切换速率 |
| is_rtr | 经典 CAN 可用遥控帧；FD 不支持遥控帧 |
| dlc | **实际字节数**，接口内部转换 HAL DLC 编码 |
| data | 最多 64 字节，接收遥控帧时清零 |

经典帧长度允许 0~8。FD 长度允许 0~8、12、16、20、24、32、48、64。
例如 9 字节不能原样编码，调用者应选择 12 字节并自行补齐；接口拒绝非法长度，不隐式填充。
同一 FDCAN 实例可发送经典帧和 FD 帧，需在 CubeMX 中启用相应 FD 模式。

## 6. 初始化与 64 字节 FD 发送

顺序：CubeMX 初始化 → config_filter → register_callback → core_can_init → 收发。
init 不清空已注册的回调；仅新增错误通知，RX/TX 通知按注册操作开启。
FDCAN 在启动前显式拒绝未匹配的标准/扩展帧，避免默认全局过滤策略绕过业务过滤器。

以下示例由 CubeMX 初始化完成后的主循环上下文调用，使用默认 FDCAN 后端及 FD + BRS 配置：

```c
#include "can_port.h"

static volatile uint32_t g_rx_id;
static volatile uint8_t g_rx_length;

static void app_can_rx(
    const st_can_frame_t *p_frame, en_core_can_fifo_t fifo)
{
    (void)fifo;
    g_rx_id = p_frame->id;
    g_rx_length = p_frame->dlc;
    /* ISR 上下文：需要留存完整帧时复制内容，不保存 p_frame。 */
}

en_core_can_status_t app_can_fd_start(void)
{
    en_core_can_status_t status;
    uint32_t i;
    st_can_frame_t frame =
    {
        .id = 0x123U,
        .is_fd = 1U,
        .is_brs = 1U,
        .dlc = 64U
    };

    for (i = 0U; i < frame.dlc; i++)
    {
        frame.data[i] = (uint8_t)i;
    }
    /* 接收全部标准帧；FDCAN 中经典/FD 由报文本身区分。 */
    status = core_can_config_filter(
        CORE_CAN1, 0U, 0U, 0U, 0U, CORE_CAN_FIFO0);
    if (CORE_CAN_OK != status)
    {
        return status;
    }
    status = core_can_register_rx_callback(
        CORE_CAN1, CORE_CAN_FIFO0, app_can_rx);
    if (CORE_CAN_OK != status)
    {
        return status;
    }
    status = core_can_init();
    if (CORE_CAN_OK != status)
    {
        return status;
    }
    return core_can_transmit_frame(CORE_CAN1, &frame, 10U);
}
```

同步发送等待本帧的 pending 位清除，超时请求中止；满 TX FIFO/mailbox 时立即返回 BUSY。
pending 清除不额外提供 TXOK 确认结果；中止请求也不保证帧从未上总线。
同步发送和轮询接收均禁止在 ISR 调用；依赖 HAL_GetTick，ISR 内使用异步发送。

## 7. 异步发送与轮询接收

以下发送函数在总线已启动后使用，也可在定时器或 TX 回调中调用：

```c
#include "can_port.h"

en_core_can_status_t app_can_send_async(void)
{
    const st_can_frame_t frame =
    {
        .id = 0x321U,
        .is_fd = 1U,
        .is_brs = 1U,
        .dlc = 12U,
        .data = {0x01U, 0x02U, 0x03U}
    };

    /* 数据在返回前复制到硬件消息 RAM，无需保留局部 frame。 */
    return core_can_transmit_frame_async(CORE_CAN1, &frame);
}
```

同一 FIFO 不混用轮询和中断；总线启动后关闭对应通知，再调用轮询 API：

```c
#include "can_port.h"

en_core_can_status_t app_can_poll(st_can_frame_t *p_frame)
{
    en_core_can_status_t status;

    status = core_can_rx_notification_disable(CORE_CAN1, CORE_CAN_FIFO0);
    if (CORE_CAN_OK != status)
    {
        return status;
    }
    return core_can_receive_frame_sync(
        CORE_CAN1, p_frame, CORE_CAN_FIFO0, 10U);
}
```

两个 FIFO 的 RX 回调独立注册，注册自动开启对应通知；传 NULL 注销并关闭通知。
RX 帧指针仅在回调期间有效。ISR 按入口时 FIFO 中的消息数量读取并分发，避免 FDCAN 新消息事件下遗留旧帧。

调用方须串行访问同一实例。不要在同步等待期间通过 TX 回调续发并复用发送缓冲区。
实现仅在 FDCAN 的投递与获取本次 buffer 标识之间短暂屏蔽本核中断，不提供线程锁、跨核互斥或业务队列。

## 8. 中断转发与完成回调

全工程仅保留一份所选后端的 HAL 回调覆盖实现；已有 UART/IIC user_isr_handlers 时合并 CAN 部分，避免文件名或保护宏冲突。

| 后端 | HAL 入口 | 平台入口 |
| --- | --- | --- |
| FDCAN | RxFifo0Callback / RxFifo1Callback | core_can_irq_rx_pending |
| FDCAN | TxBufferCompleteCallback | core_can_irq_tx_complete |
| FDCAN | ErrorCallback | core_can_irq_error |
| FDCAN | ErrorStatusCallback | core_can_irq_error_status |
| bxCAN | 三个 TxMailboxCompleteCallback | core_can_irq_tx_complete |
| bxCAN | 两个 RxFifoMsgPendingCallback | core_can_irq_rx_pending |
| bxCAN | ErrorCallback | core_can_irq_error |

注册 TX 回调自动打开完成通知，传 NULL 关闭。TX 参数是完成缓冲区的位掩码，可包含多个位，不是固定 0/1/2 索引。
若只需通知业务继续发送，可以忽略该参数。

错误回调收到 HAL GetError 返回码；FDCAN ErrorStatusCallback 则传递 FDCAN_IT_BUS_OFF、ERROR_WARNING、ERROR_PASSIVE 等状态变化位。
Bus-Off 等事件表示状态发生变化，若要判断当前是否处于该状态，工程可通过 HAL 的协议状态查询接口获取。
回调都在 ISR 执行，禁止阻塞或调用同步收发。

## 9. 过滤器后端差异

| 项目 | FDCAN | bxCAN |
| --- | --- | --- |
| ID/mask 输入 | 直接右对齐，HAL 内部处理布局 | 封装处理标准 ID << 5、扩展 ID << 3 |
| 标准/扩展类型 | 分属两组过滤器列表 | IDE 位加入掩码，强制匹配类型 |
| filter_bank | 每实例、每种 ID 类型各自从 0 编号 | 单 CAN 0~13；双 CAN 固定以 14 分界 |
| 未匹配报文 | init 设置全局拒绝 | 硬件按启用的过滤器匹配 |
| 遥控帧 | 经典遥控帧仍按过滤器匹配 | 不使用 RTR 位过滤 |

过滤器和回调应在 init 前全部配置。通用版 init 启动所有已配置实例；中途失败不会回滚已启动的实例。

## 10. FOC 简化版与排查

FOC 版直接使用 hfdcan1，选择 bxCAN 时使用 hcan1，不建实例表；接口移除 instance 参数。
仅复制 [core_can.h](./03_Firmware/FOC简化版/04_platform/platform_mcu/can/inc/core_can.h)
和 [core_can.c](./03_Firmware/FOC简化版/04_platform/platform_mcu/can/src/core_can.c)。
默认不开 RX/TX 通知；工程自行实现 HAL 回调，通过 rx_notification_enable 开启接收通知。
TX 完成通知由工程侧使用对应 HAL 接口激活。芯片配置仍由 CubeMX 负责。

| 现象 | 检查 |
| --- | --- |
| 找不到 fdcan.h | 是否生成 FDCAN 文件；经典 bxCAN 工程应统一选择 CORE_CAN_USE_FDCAN=0 |
| NOT_READY | 实例表是否绑定、CubeMX 初始化是否执行 |
| FD 参数错误 | 长度是否可编码、是否误用 RTR、CubeMX 是否启用 FD/BRS |
| FD 超时或数据错误 | 仲裁/数据段位时序、消息 RAM 元素大小、收发器与对端是否支持 FD |
| 过滤器失效 | 配置数量、索引与 ID 类型是否一致 |
| 回调不来 | NVIC、HAL IRQ 转发、通知注册及 HAL 动态回调选项 |
| 轮询无帧 | 是否仍开启同一 FIFO 的中断通知 |
