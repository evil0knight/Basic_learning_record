## 0. 它长什么样

```text
你的驱动 / 业务代码
      │  core_i2c_mem_read / _sync / core_i2c_submit / _async
┌─────▼────────────────────────┐
│  Port（bare 或 os，二选一）    │  i2c_port_bare.c  或  i2c_port_os.c
│  锁 / 超时 / 同步等待 / 队列   │
└─────┬────────────────────────┘
      │  i2c_bus_mem_read / _dma / register_*_callback / irq_*
┌─────▼────────────────────────┐
│  Bus（唯一一份）               │  i2c_bus.c + soft_i2c.c
│  协议 / HAL / DMA / busy      │
└─────┬────────────────────────┘
      │  HAL_I2C_Mem_Read / _DMA / Master_Abort_IT
┌─────▼────────────────────────┐
│  STM32 HAL + CubeMX           │  i2c.c / i2c.h / stm32xxxx_hal_i2c.c
└──────────────────────────────┘
```

| 层 | 职责 | 不做 |
| --- | --- | --- |
| Bus | HAL、DMA、`busy`、中断分发、阻塞/启动传输 | 不创建 OS 资源、不加锁、不判超时 |
| 裸机 Port | 请求队列、临界区、`core_time_get()`、超时判定 | 不碰 HAL 细节 |
| RTOS Port | 每总线注册的 mutex/sema、`osal_sema_take/give` | 不创建内核资源 |
| 你的驱动 | 业务逻辑、设备地址、寄存器含义 | 不碰 I2C 时序、不碰锁 |

**Bus 只写一份，Port 按环境二选一。**

## 1. 复制哪些文件

### 1.1 必须复制的

| 文件 | 作用 | 要不要改 |
| --- | --- | --- |
| `bus/inc/i2c_port_types.h` | 状态码、槽位号枚举、回调类型、`core_i2c_request_t` | 要（加自己的槽位名） |
| `bus/inc/i2c_bus.h` | Bus 公开接口、`CORE_I2C_HW_ENABLE` | 一般不改 |
| `bus/inc/i2c_bus_config.h` | **槽位表** | **一定要改** |
| `bus/inc/soft_i2c.h` | 软件 I2C 内部接口 | 不改 |
| `bus/src/i2c_bus.c` | Bus 实现 | 不改 |
| `bus/src/soft_i2c.c` | 软件 I2C 位翻转时序 | 不改 |
| `port/bare/i2c_port_bare.h` + `.c` | 裸机 Port | 不改 |
| `port/os/i2c_port_os.h` + `.c` | RTOS Port | 不改 |

`port/bare` 和 `port/os` **只能选一套**，两个 `.c` 都加进工程会重复定义
`core_i2c_init` / `core_i2c_mem_read` 等符号。

| 环境 | 选哪套 | 锁和完成 |
| --- | --- | --- |
| 裸机主循环、FOC 电流环中断 | `port/bare` | `platform_critical_enter/exit` + 标志位 |
| FreeRTOS 任务 | `port/os` | 每总线注册的 mutex + 完成信号量 |

### 1.2 不用复制，但工程里必须已有

| 依赖 | 谁在用 | 提供什么 | 来源 |
| --- | --- | --- | --- |
| `main.h` | `i2c_bus.h`、`gpio_port.h` | `I2C_HandleTypeDef`、`GPIO_TypeDef`、`GPIO_PinState` | CubeMX 生成 |
| `i2c.h` / `i2c.c` + HAL I2C Driver | 硬件 I2C | `hi2c1` 等句柄、`HAL_I2C_Mem_Read/Write/_DMA`、`HAL_I2C_Master_Abort_IT` | CubeMX 生成 |
| `gpio/inc/gpio_port.h` + `gpio/src/gpio_port.c` | `soft_i2c.c`（**无条件下引用**） | `core_gpio_write_pin_direct()`、`core_gpio_read_pin_direct()` | 平台层，见 [GPIO Port](../代码架构/firmware/04_platform/platform_mcu/gpio/inc/gpio_port.h) |
| `time/inc/time_port.h` | 裸机 Port | `core_time_get()` 毫秒时间戳 | 平台层 |
| `critical/inc/critical_port.h` | 裸机 Port | `platform_critical_enter/exit()` | 平台层 |
| `osal.h` + OSAL 实现 | RTOS Port | `osal_mutex_*`、`osal_sema_*`、`osal_critical_*` | 中间件 |

> **`gpio_port.c` 即使你只用硬件 I2C 也必须加进编译**——`soft_i2c.c` 无条件
> `#include "../../../gpio/inc/gpio_port.h"` 并通过 `core_gpio_*_direct()` 读写引脚，
> 链接时少这个 `.c` 会报 `undefined reference to core_gpio_write_pin_direct`。

## 2. 目录必须这么摆

`soft_i2c.c` 和 `i2c_port_bare.c` 里的 include 用的是**硬编码相对路径**：

```c
/* bus/src/soft_i2c.c */
#include "../../../gpio/inc/gpio_port.h"

/* port/bare/i2c_port_bare.c */
#include "../../../critical/inc/critical_port.h"
#include "../../../time/inc/time_port.h"
```

从 `.../platform_mcu/i2c/bus/src/` 往上退三层正好是 `platform_mcu/`，
所以目录只能是：

```text
04_platform/platform_mcu/
├── i2c/
│   ├── bus/
│   │   ├── inc/   i2c_port_types.h  i2c_bus.h  i2c_bus_config.h  soft_i2c.h
│   │   └── src/   i2c_bus.c  soft_i2c.c
│   └── port/
│       └── bare/   i2c_port_bare.h  i2c_port_bare.c
│           （或 os/）
├── gpio/
│   ├── inc/       gpio_port.h
│   └── src/       gpio_port.c
├── time/
│   └── inc/       time_port.h
└── critical/
    └── inc/       critical_port.h
```

想换个位置就必须同步改上面那三行 `#include`，**不能只改 include 路径配置**，
因为写的是相对路径不是尖括号搜索。

应用层的接入口放这儿：

```text
01_app/app_isr_handlers/
├── user_isr_handlers.h
└── user_isr_handlers.c
```

## 3. 工程配置

### 3.1 头文件搜索路径

| 路径 | 谁需要 | 为什么 |
| --- | --- | --- |
| `04_platform/platform_mcu/i2c/bus/inc` | 全部 | `i2c_bus.h`、`i2c_port_types.h` |
| `04_platform/platform_mcu/i2c/port/bare` 或 `.../port/os` | 全部 | 你调用的 `core_i2c_*` 在这里声明 |
| `04_platform/platform_mcu/gpio/inc` | 全部 | `soft_i2c.c` 用 |
| `04_platform/platform_mcu/time/inc` | 裸机 | `core_time_get()` |
| `04_platform/platform_mcu/critical/inc` | 裸机 | `platform_critical_*()` |
| `03_os/.../osal/inc` | RTOS | `osal.h` |
| `Core/Inc`（CubeMX） | 全部 | `main.h`、`i2c.h` |

### 3.2 加入编译的源文件

```text
i2c_bus.c
soft_i2c.c
i2c_port_bare.c        <-- 二选一
i2c_port_os.c          <-- 二选一
gpio_port.c            <-- 别忘
```

### 3.3 编译选项

- **C99 或更高**。槽位表用了指定初始化器 `[CORE_I2C_PORT_ENCODER1] = {...}`。
  Keil AC5 要在 Options → C/C++ → 勾 **C99 Mode**；AC6 默认即可。
- 栈：RTOS Port 的同步接口在调用者任务上下文等信号量，正常任务栈即可；
  别把 `_sync` 放进中断（裸机超时靠 `core_time_get()`，中断里 SysTick 不涨会死转）。

### 3.4 可覆盖的宏

| 宏 | 默认 | 定义位置 | 说明 |
| --- | --- | --- | --- |
| `CORE_I2C_HW_ENABLE` | `1` | `i2c_bus.h` | 置 `0` 表示只用软件 I2C，硬件槽位和 HAL 相关代码全被裁掉 |
| `CORE_I2C_QUEUE_DEPTH` | `4` | `i2c_port_types.h` | 裸机每条总线的请求队列深度，满了 `core_i2c_submit` 返回 `CORE_I2C_ERR_BUSY` |
| `CORE_I2C_ABORT_TIMEOUT_MS` | `5` | `i2c_bus.h` | abort 之后等 `AbortCplt` 的兜底超时，等不到就强制复位总线 |

`CORE_I2C_HW_ENABLE == 0` 时，`i2c_bus_config.h` 里的槽位必须全部改成
`CORE_I2C_TYPE_SOFTWARE`，否则 `st_core_hardware_i2c_config_t` 不存在会编译失败。

## 4. CubeMX 要做什么

### 4.1 硬件 I2C

1. **Connectivity → I2Cx → I2C**
   - Speed Mode：`Fast Mode`（400 kHz）或 `Standard Mode`（100 kHz）
   - 7 位地址（默认）
2. **DMA Settings → Add**
   - `I2Cx_RX`：Mode = **Normal**，**不要 Circular**
   - `I2Cx_TX`：Mode = **Normal**，**不要 Circular**
   - 优先级至少 Medium，别低于串口
3. **NVIC Settings**
   - `I2Cx event interrupt` ✅
   - `I2Cx error interrupt` ✅
   - 对应的 DMA 通道中断 ✅
4. **GPIO** 引脚设 User Label，方便在 `main.h` 里看到物理资源宏
5. 生成代码后确认 `i2c.h` 里有 `extern I2C_HandleTypeDef hi2c1;`

> 只用模式①（死等）时 DMA 和 NVIC 可以不开。
> 模式②③（同步/异步）**必须**开 DMA + event + error 中断，否则完成回调永远不来。

### 4.2 软件 I2C

1. 把 SCL、SDA 两个引脚配成 **GPIO_Output**
2. Output level：`High`
3. GPIO mode：**Output Open Drain**
4. Pull-up：`Pull-up`（或外部上拉电阻）
5. **不要**把这两个脚配成 I2C 复用功能——软件 I2C 要自己翻转电平
6. 把引脚定义成 User Label

`GPIO_TypeDef` 是 `GPIOA` 这类端口指针，`uint16_t` 是 `GPIO_PIN_6` 这类引脚掩码，
两者都要填到槽位表里。

## 5. 填槽位表 `i2c_bus_config.h`

这是**唯一必须改的文件**。一条物理总线占一个槽位。

### 5.1 硬件 I2C

```c
/* i2c_bus_config.h */
#include "i2c.h"

static st_core_i2c_slot_t g_i2c_slots[CORE_I2C_PORT_MAX] = {
    [CORE_I2C_PORT_ENCODER1] = {
         .type = CORE_I2C_TYPE_HARDWARE,
         .config.hardware = {
             .handle = &hi2c1
         }
    }
};
```

### 5.2 软件 I2C

```c
static void board_delay_us(uint32_t delay_us)
{
    /* 用 DWT 或 TIM 实现，别用空循环 */
}

static st_core_i2c_slot_t g_i2c_slots[CORE_I2C_PORT_MAX] = {
    [CORE_I2C_PORT_ENCODER1] = {
         .type = CORE_I2C_TYPE_SOFTWARE,
         .config.software = {
             .scl_port       = GPIOB,
             .scl_pin        = GPIO_PIN_6,
             .sda_port       = GPIOB,
             .sda_pin        = GPIO_PIN_7,
             .half_period_us = 5U,          /* 约 100 kHz */
             .delay_us       = board_delay_us
         }
    }
};
```

### 5.3 两条总线混用

```c
static st_core_i2c_slot_t g_i2c_slots[CORE_I2C_PORT_MAX] = {
    [CORE_I2C_PORT_ENCODER1] = {
         .type = CORE_I2C_TYPE_HARDWARE,
         .config.hardware = { .handle = &hi2c1 }
    },
    [CORE_I2C_PORT_SENSOR] = {
         .type = CORE_I2C_TYPE_SOFTWARE,
         .config.software = {
             .scl_port = GPIOB, .scl_pin = GPIO_PIN_6,
             .sda_port = GPIOB, .sda_pin = GPIO_PIN_7,
             .half_period_us = 5U, .delay_us = board_delay_us
         }
    }
};
```

> **这个头文件只被 `i2c_bus.c` 包含。** `g_i2c_slots` 是 `static`，别的 `.c`
> 不要再 `#include "i2c_bus_config.h"`，否则每个翻译单元各生成一份槽位表副本，
> 改了配置却不生效，非常难查。

## 6. 接中断入口

把 [`01_app/app_isr_handlers/user_isr_handlers.c`](./01_app/app_isr_handlers/user_isr_handlers.c)
合并进工程的 `01_app/app_isr_handlers/`。

它只做转发，四个 HAL 回调各对应 Bus 的一个入口：

| HAL 弱回调 | 转发到 | 什么时候来 |
| --- | --- | --- |
| `HAL_I2C_MemRxCpltCallback` | `i2c_bus_irq_mem_rx_complete()` | DMA 读完成 |
| `HAL_I2C_MemTxCpltCallback` | `i2c_bus_irq_mem_tx_complete()` | DMA 写完成 |
| `HAL_I2C_ErrorCallback` | `i2c_bus_irq_error()` | 传输中出错（NACK/BERR/ARLO/OVR） |
| `HAL_I2C_AbortCpltCallback` | `i2c_bus_irq_abort_complete()` | 你调 `Abort_IT` 之后中止完成 |

三个硬性要求：

1. **全工程只保留一份**这四个回调。CubeMX 生成的代码或别的驱动里如果也有同名实现，
   删掉那边的，只留这份。
2. **只在模式②③需要**。只用模式①（普通 HAL 轮询）时不用拷这个文件。
3. 回调在中断上下文执行，里面不要再做阻塞操作。

## 7. RTOS 额外：资源表

锁和信号量**不在 I2C 层创建**，统一由 App 的资源表管理。

### 7.1 头文件加两个索引

```c
/* user_task_reso_config.h */
typedef enum
{
    USER_MUTEX_IDX_I2C1 = 0,
    USER_MUTEX_IDX_MAX
} user_mutex_idx_t;

typedef enum
{
    USER_SEMA_IDX_I2C1_DONE = 0,
    USER_SEMA_IDX_MAX
} user_sema_idx_t;
```

### 7.2 资源表启用这两项

```c
/* user_task_reso_config.c */
user_mutex_config_t g_user_mutexes[USER_MUTEX_IDX_MAX] =
{
    [USER_MUTEX_IDX_I2C1] = {true, NULL}
};

user_sema_config_t g_user_semaphores[USER_SEMA_IDX_MAX] =
{
    [USER_SEMA_IDX_I2C1_DONE] = {true, true, 1U, 0U, NULL}
};
```

`user_os_resources_init()` 遍历这两张表创建内核对象；
`user_os_resources_deinit()` 负责释放。

### 7.3 注册给 Port

```c
/* user_task_reso_config.c */
void user_i2c_resource_register(void)
{
    (void)core_i2c_register_mutex(CORE_I2C_PORT_ENCODER1,
                                  user_mutex_get(USER_MUTEX_IDX_I2C1));
    (void)core_i2c_register_semaphore(CORE_I2C_PORT_ENCODER1,
                                      user_sema_get(USER_SEMA_IDX_I2C1_DONE));
}
```

## 8. 初始化顺序

### 8.1 裸机

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_DMA_Init();          /* 必须在 I2C 之前 */
MX_I2C1_Init();         /* CubeMX 已按此顺序生成 */

if (CORE_I2C_OK != core_i2c_init())
{
    Error_Handler();
}

/* 开始传输 */
```

### 8.2 RTOS

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_DMA_Init();
MX_I2C1_Init();

user_os_resources_init();        /* 1. 创建 mutex / sema，句柄进表 */
(void)core_i2c_init();           /* 2. Bus + Port 初始化 */
user_i2c_resource_register();    /* 3. 把句柄注入 Port */

/* 启动任务 */
```

顺序要点：

1. `core_i2c_init()` 必须在 `MX_I2Cx_Init()` 之后——它要读 `hi2c1` 的状态。
2. `user_i2c_resource_register()` 必须在 `user_os_resources_init()` 之后——
   句柄要先创建出来。
3. 注册之前调用同步接口会走「未注册」退化路径（不加锁 / 退回阻塞传输）。

## 9. 怎么用（三种模式）

判断标准只有一条：**结果在哪里拿**。

| | 在本函数里拿到结果 | 结果在别处拿 |
| --- | --- | --- |
| **普通 HAL**（CPU 在 HAL 内轮询） | ① 死等 | ✗ 没意义 |
| **DMA** | ② 同步 | ③ 异步 |

| 场景 | 用哪个 | 搬运 | 结果怎么拿 |
| --- | --- | --- | --- |
| 初始化、低频、写一条命令 | `core_i2c_mem_read/write`（①） | 普通 HAL 轮询 | 返回即完成 |
| 要 DMA，但这次必须拿到结果才能往下走 | `core_i2c_mem_read/write_sync`（②） | DMA | 裸机：反复调用轮询自己的 `done`；RTOS：阻塞等信号量 |
| 高频采样，不想阻塞 | `core_i2c_submit` / `core_i2c_read_async`（③） | DMA | 别处（回调 / 已注册的信号量） |

> ⚠️ **裸机 Port 和 RTOS Port 的 `_sync` 调用形态不一样**，别照抄：
>
> ```c
> /* 裸机：非阻塞，每次调用立刻返回，反复调来推进 */
> while (1)
> {
>     st = core_i2c_mem_read_sync(...);
>     if (CORE_I2C_OK == st) { 用(buf); break; }
> }
>
> /* RTOS：一次调用阻塞到完成或超时 */
> st = core_i2c_mem_read_sync(...);
> ```

### 9.1 ① 死等 — 普通 HAL

裸机和 RTOS 一样：

```c
uint8_t buf[2];
en_core_i2c_status_t status;

status = core_i2c_mem_read(CORE_I2C_PORT_ENCODER1,
                           0x36U,                   /* 七位设备地址 */
                           0x0CU,                   /* 寄存器地址 */
                           CORE_I2C_MEM_ADDR_8BIT,
                           buf, 2U,
                           10U);                    /* 超时 ms */
if (CORE_I2C_OK != status)
{
    /* 失败处理 */
}
```

返回即完成。RTOS 下这把锁是 `core_i2c_register_mutex()` 注册的那把。

### 9.2 ② 同步 — DMA，非阻塞轮询（裸机）

```c
uint8_t buf[2];
en_core_i2c_status_t st;

while (1)
{
    st = core_i2c_mem_read_sync(CORE_I2C_PORT_ENCODER1,
                                0x36U, 0x0CU,
                                CORE_I2C_MEM_ADDR_8BIT,
                                buf, 2U, 10U);

    if (CORE_I2C_OK == st)      { 用(buf); break; }     /* 完成 */
    if (CORE_I2C_PENDING == st) { continue; }           /* 还没完，下一圈 */
    break;                                              /* 出错 */
}
```

三次调用的语义：

| 第几次 | 函数做什么 | 返回 |
| --- | --- | --- |
| 第 1 次 | 端口空闲 → 组装请求 + `submit` → 记起始时间 | `CORE_I2C_PENDING` |
| 第 2..N 次 | 只查这一笔自己的 `done` 和超时 | `CORE_I2C_PENDING` 或结果 |
| 完成后 | 取走 `status`、清 `done` | 本次传输结果 |

**函数全程不等待**，CPU 不会停在 `_sync` 里。超时按「首次提交 → 当前」的毫秒差判定，超了会自动 `abort` 并返回 `CORE_I2C_ERR_TIMEOUT`。

两个必须注意的：

1. **轮询阶段的入参会被忽略**。第 2 次以后传的 `p_data` 不生效，数据进的是**第 1 次提交**时的那个 buffer。单使用者、参数固定没问题；两个寄存器交替读就会串。
2. **不要在中断里调 `_sync`**。裸机超时靠 `core_time_get()`，中断里 SysTick 不涨会真的死转。

RTOS 的 `_sync` 不一样，它是 `osal_sema_take(sema, ticks)` **阻塞**等，一次调用直接返回结果，不轮询。

### 9.3 ③ 异步 — DMA，别处等

**裸机：填请求结构，提交**

```c
static void on_i2c_done(core_i2c_port_id_t    port,
                        uint8_t               device_address_7bit,
                        en_core_i2c_status_t  status,
                        void                 *p_user_data)
{
    /* 中断上下文：只置标志、发队列、给信号量，别阻塞 */
}

core_i2c_request_t req =
{
    .port                = CORE_I2C_PORT_ENCODER1,
    .device_address_7bit = 0x36U,
    .memory_address      = 0x0CU,
    .address_size        = CORE_I2C_MEM_ADDR_8BIT,
    .p_data              = buf,
    .size                = 2U,
    .is_write            = 0U,
    .timeout_ms          = 10U,
    .pf_done             = on_i2c_done,
    .p_user_data         = my_ctx,
    .done                = 0U,
};

(void)core_i2c_submit(&req);      /* 入队 + 立刻尝试启动 */
```

不想挂回调也可以，`pf_done` 传 `NULL`，改成自己查 `req.done`：

```c
if (0U != req.done)
{
    用(req.p_data);
    req.done = 0U;                /* 取走后清掉，才能再提交下一次 */
}
```

`core_i2c_submit()` 会把结果直接回写进**你传进去的那个 `req`**，所以队列里排多笔时每笔的 `done/status` 各自独立。

**RTOS：启动后返回，别处等信号量**

```c
(void)core_i2c_read_async(CORE_I2C_PORT_ENCODER1,
                          0x36U, 0x0CU,
                          CORE_I2C_MEM_ADDR_8BIT,
                          buf, 2U,
                          NULL, NULL);       /* 回调可空，靠信号量 */

(void)osal_sema_take(user_sema_get(USER_SEMA_IDX_I2C1_DONE),
                     osal_ms_to_ticks(10U));
```

### 9.4 查看错误

```c
uint32_t raw = core_i2c_get_error_code(CORE_I2C_PORT_ENCODER1);
/* raw == HAL_I2C_ERROR_AF → 从机没应答（地址错了 / 器件没上电） */
```

也可以注册 `i2c_bus_register_error_callback()` 拿旁路通知：

```c
static void on_i2c_error(core_i2c_port_id_t port,
                         uint8_t            device_address_7bit,
                         uint32_t           error_code)
{
    /* 中断上下文 */
}
```

### 9.5 中止

```c
(void)core_i2c_abort(CORE_I2C_PORT_ENCODER1);
```

超时后 `AbortCplt` 迟迟不来，用 Bus 的兜底复位：

```c
(void)i2c_bus_recover(CORE_I2C_PORT_ENCODER1);
```

## 10. 多加一条总线

以加 I2C2 为例，三步：

1. **`i2c_port_types.h`** 枚举里加名字

   ```c
   typedef enum
   {
       CORE_I2C_PORT_ENCODER1 = 0,
       CORE_I2C_PORT_SENSOR,          /* 新增 */
       CORE_I2C_PORT_MAX = 8
   } core_i2c_port_id_t;
   ```

2. **`i2c_bus_config.h`** 加一个槽位

   ```c
   [CORE_I2C_PORT_SENSOR] = {
        .type = CORE_I2C_TYPE_HARDWARE,
        .config.hardware = { .handle = &hi2c2 }
   }
   ```

3. **RTOS 再加一组资源**：`USER_MUTEX_IDX_I2C2`、`USER_SEMA_IDX_I2C2_DONE`，
   表里启用，再在 `user_i2c_resource_register()` 里多注册一行。

裸机到此结束，不需要额外资源。

## 11. 软件 I2C 怎么用

- 槽位 `.type = CORE_I2C_TYPE_SOFTWARE`，填 `config.software`。
- **不支持 DMA**：`core_i2c_submit` 就地做完再回调，`i2c_bus_mem_*_dma()`
  返回 `CORE_I2C_ERR_UNSUPPORTED`。
- RTOS 下软件槽位**不能用 mutex**，Port 自动改用
  `osal_critical_enter/exit` + 普通 HAL 路径。
- `half_period_us` 决定速率：`5U` 约 100 kHz，`2U` 约 250 kHz（受上拉和线容限制）。
- `delay_us` 必须是**真正的微秒延时**（DWT 或 TIM），空循环在优化后会失真。
- 同一个槽位表里软件和硬件可以混用。

## 12. 自检表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `undefined reference to core_gpio_write_pin_direct` | 没把 `gpio_port.c` 加进编译 | 加进去 |
| `undefined reference to core_time_get` | 裸机 Port 缺 `time_port` | 加 `time` 模块 |
| `undefined reference to osal_sema_take` | RTOS Port 缺 OSAL | 加 OSAL 或改用裸机 Port |
| `st_core_hardware_i2c_config_t` 未定义 | `CORE_I2C_HW_ENABLE == 0` 但槽位还写硬件 | 槽位改软件，或把宏改回 1 |
| `st_core_i2c_slot_t` 未定义 | 有人直接 `#include "i2c_bus_config.h"` | 只在 `i2c_bus.c` 里包含 |
| 重复定义 `core_i2c_init` | `port/bare` 和 `port/os` 都加进编译 | 只留一套 |
| 链接报重复的 `HAL_I2C_MemRxCpltCallback` | 工程里有两份 HAL 回调 | 全工程只留一份 |
| `core_i2c_mem_read` 永远返回 `CORE_I2C_ERR_TIMEOUT` | 普通 HAL 路径下 `timeout_ms == 0`，HAL 语义是「立即超时」 | **统一传非 0**（如 `10U`） |
| `_sync` 一直返回 `CORE_I2C_PENDING` | DMA 中断没开 / NVIC 没使能，完成标志永远不置 | 检查 CubeMX DMA + event + error 中断 |
| `_sync` 一直超时 | DMA 配成了 `Circular` | 改成 `Normal` |
| `_sync` 拿到的数据是上一次的 | 轮询阶段改了 `p_data`，但入参被忽略 | 每次读用同一个 buffer，或改用 `submit` + 自己的 `req` |
| 异步完成回调从没被调 | 没接 `user_isr_handlers.c`，或中断没开 | 见第 6 节 |
| 硬件 I2C 读不到数据，`HAL_I2C_ERROR_AF` | 地址错（8 位 vs 7 位） | 传 7 位地址，Port 会自己左移 |
| 软件 I2C 波形是方波但器件不应答 | 引脚配成了 I2C 复用，不是开漏输出 | 改回 `GPIO_Output` + `Open Drain` |
| 同一总线多器件互相踩 | 没注册 mutex | `core_i2c_register_mutex()` |

### 四条最容易踩的

1. **`timeout_ms` 统一传非 0。** 裸机 `_sync` 里 `0` 是「不限时」，
   但普通 HAL 接口里 `0` 会被 HAL 当成「立即超时」——两者语义不一致，
   干脆一律传 `10U` 这种正数。
2. **裸机 `_sync` 是非阻塞的。** 它提交完就返回 `CORE_I2C_PENDING`，
   要反复调才拿得到结果；只调用一次是永远读不到数据的。
3. **`i2c_bus_config.h` 只给 `i2c_bus.c` 用。**
4. **`user_isr_handlers.c` 全工程只有一份。**
