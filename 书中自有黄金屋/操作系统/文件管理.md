## 核心概念：FCB 与 inode

**FCB（File Control Block）** 是 OS 用来描述一个文件的控制块。Unix 里叫 **inode**，Windows 里嵌在目录项或 MFT 中。每个文件都有唯一的 FCB/inode。

磁盘上的 FCB/inode 至少包含：

| 字段 | 含义 |
| ---- | ---- |
| 文件类型与权限 | 普通文件/目录/设备，rwx |
| 文件大小 | 字节数 |
| 时间戳 | 创建/最后访问/最后修改时间 |
| 硬链接计数 | 指向本 inode 的文件名数量 |
| 数据块指针 | 文件的物理块号（直接块 / 一级间接 / 二级间接） |

> **关键**：FCB/inode 里**不存文件名**——文件名存在目录里。

### 文件与目录的关系

- **目录也是文件**，内容是 `(文件名 → inode号)` 的映射表。
- 打开文件时 OS 做的就是：**按路径逐级查目录 → 拿到 inode 号 → 把 inode 从磁盘加载到内存的 inode 缓存 → 进程拿到文件描述符**。

### 打开文件时的内存结构

| 内存结构 | 存什么 | 生命周期 |
| -------- | ------ | -------- |
| **inode 缓存** | 文件的属性、数据块指针（磁盘 inode 的副本） | 文件被访问时加载，持续缓存直到内存紧张回收 |
| **dentry 缓存** | `(文件名, inode号)` 的映射，就是打开目录时加载进来的 | 路径解析时创建，持续缓存 |
| **打开文件表**（系统级 + 进程级） | 当前读写偏移、打开模式（r/w/a）、引用计数 | 文件被 `open` 到 `close` |

打开文件的大致流程：

```
open("/docs/note.txt", O_RDONLY)
  → 查 dentry 缓存: "/" 的 inode 是多少
  → 查 dentry 缓存: "docs" → inode 号, 加载 docs 的目录项列表到内存
  → 查 dentry 缓存: "note.txt" → inode 号
  → 把 note.txt 的 inode 从磁盘加载到 inode 缓存
  → 在系统打开文件表中建一条记录
  → 在进程打开文件表（fd 表）中建一条记录,指向系统表
  → 返回 fd
```

### 文件管理主要功能

1. **按名存取**：用户用文件名操作，OS 负责文件名 → inode → 物理块的翻译
2. **目录管理**：目录的增删查改，本质是操作 `(文件名, inode号)` 映射表
3. **存储空间管理**：分配和回收磁盘块
4. **共享与保护**：多进程访问同一文件时的权限控制
5. **统一接口**：`open/read/write/close`，屏蔽不同文件系统差异

## 文件共享

| 类型 | 原理 | 删除源文件后 |
| ---- | ---- | ------------ |
| **硬链接** | 多个文件名指向同一个 inode，inode 里记录链接计数 | 文件内容仍在（计数 > 0 就还在） |
| **软链接** | 单独新建一个文件，内容是目标路径字符串 | 软链接失效（断链） |

**一句话**：硬链接连 inode，软链接连路径。

## 访问控制

基本模型：**rwx × 所有者-组-其他人**

实际检查顺序：进程访问文件时，OS 先拿进程的 uid/gid 和文件的 inode 权限位对比，通过才放行。

## 文件的物理分配方式

| 方式 | 原理 | 优点 | 缺点 |
| ---- | ---- | ---- | ---- |
| **连续分配** | 文件占一串连续磁盘块 | 顺序读写快 | 外部碎片，文件拓展困难 |
| **链接分配** | 每个块存下一块指针 | 无外部碎片，易拓展 | 随机访问差，指针占空间 |
| **索引分配** | 一个索引块集中存所有数据块号 | 随机访问好 | 索引块本身也占空间 |

现代文件系统普遍用**索引分配**（ext4 的多级索引、NTFS 的 MFT 运行列表）。

## 文件系统布局

### 磁盘上

| 区域 | 内容 |
| ---- | ---- |
| 引导块 | 启动引导代码，通常放卷开头 |
| 超级块 | 文件系统全局信息：块大小、总块数、空闲块数、inode 总数 |
| inode 区 | 所有 inode（FCB），每个文件一个 |
| 数据区 | 文件内容 + 目录内容（目录的"数据"就是文件名→inode表） |

### 内存中

| 结构 | 内容 |
| ---- | ---- |
| 挂载表 | 已挂载文件系统的超级块副本 |
| inode 缓存 | 正在使用的 inode 副本 |
| dentry 缓存 | 路径分量 → inode 的映射，加速路径解析 |
| 打开文件表 | 当前系统内所有打开的文件及其读写位置 |

## 空闲空间管理

| 方法 | 原理 | 适合场景 |
| ---- | ---- | -------- |
| **空闲表法** | 记录 `(起始块号, 长度)`，类似动态分区 | 连续分配 |
| **空闲链表法** | 把所有空闲块串成链表 | 简单但效率低 |
| **位示图法** | 每个块对应 1 bit：0 空闲 / 1 已用 | 现代主流，易找连续空闲块 |
| **成组链接法** | 把连续空闲块号分组，一组存下一组指针，批量出入 | Unix 传统做法 |

## 虚拟文件系统（VFS）

VFS 是 OS 的文件系统抽象层，对上统一 `open/read/write/close`，对下适配 ext4 / FAT / NFS 等具体实现。

四个核心对象：

| 对象 | 含义 | 存在位置 |
| ---- | ---- | -------- |
| **super_block** | 代表一个已挂载的文件系统实例 | 磁盘 → 内存挂载表 |
| **inode (Vnode)** | 代表一个文件的属性 + 数据位置 | 磁盘 inode 区 → 内存 inode 缓存 |
| **dentry** | 目录项，关联一个路径分量到 inode | 仅内存，解析时创建 |
| **file** | 代表文件在一次打开中的状态（偏移量、打开模式） | 仅内存，进程打开文件表 |
