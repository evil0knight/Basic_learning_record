## 标准概述

IEEE 754（Institute of Electrical and Electronics Engineers 754）是目前最通用的浮点数存储标准，几乎所有现代 CPU 和编程语言都遵循此标准。

---

## 浮点数的数学表示

任何浮点数都可以写成科学计数法的形式：

$$(-1)^s \times 1.M \times 2^{E}$$

| 符号 | 名称 | 说明 |
|------|------|------|
| $s$ | 符号位（Sign） | 0 = 正数，1 = 负数 |
| $1.M$ | 尾数（Mantissa / Significand） | 规格化后，整数位恒为 1，只需存小数部分 $M$ |
| $E$ | 指数（Exponent） | 实际指数经过偏置处理后存储 |

> 整数位的 1 不需要存储，称为**隐含位（hidden bit）**，可以省一位存储空间。

---

## 两种精度格式

| | 单精度（float，32位） | 双精度（double，64位） |
|---|---|---|
| 符号位 | 1 位 | 1 位 |
| 指数位 | 8 位 | 11 位 |
| 尾数位 | 23 位 | 52 位 |
| 指数偏置值 | 127 | 1023 |

### 存储布局（以单精度为例）

```
31      30      23  22                    0
 ┌───┬────────────┬────────────────────────┐
 │ S │  Exponent  │       Mantissa         │
 │1位│    8位     │         23位           │
 └───┴────────────┴────────────────────────┘
```

---

## 指数的偏置存储（Biased Exponent）

指数不直接存补码，而是加上一个**偏置值（Bias）**后存储为无符号整数：

$$\text{存储值} = \text{真实指数} + \text{Bias}$$

- 单精度 Bias = **127**，指数范围：$-126 \sim +127$（实际存储 1～254，0 和 255 保留）
- 双精度 Bias = **1023**，指数范围：$-1022 \sim +1023$

**为什么用偏置而不用补码？**
偏置表示法可以直接用无符号整数比较大小，硬件实现更简单。

---

## 完整转换示例

### 将 $-12.625$ 转为 IEEE 754 单精度

**Step 1：转二进制**

$$12 = 1100_2, \quad 0.625 = 0.101_2$$

$$\Rightarrow 12.625 = 1100.101_2$$

**Step 2：规格化**

$$1100.101_2 = 1.100101 \times 2^3$$

**Step 3：填各字段**

| 字段 | 值 | 说明 |
|------|-----|------|
| 符号位 S | `1` | 负数 |
| 真实指数 | 3 | |
| 存储指数 | $3 + 127 = 130 = 10000010_2$ | |
| 尾数 M | `10010100000000000000000` | 去掉整数位的 1，补零到 23 位 |

**结果：**

```
1 | 10000010 | 10010100000000000000000
```

十六进制：`0xC1480000`

| 存储指数 | 尾数 M | 含义 |
|----------|--------|------|
| 全 0（0） | 全 0 | $\pm 0$ |
| 全 0（0） | 非零 | 非规格化数（极小值，整数位为 0） |
| 全 1（255/2047） | 全 0 | $\pm\infty$（无穷大） |
| 全 1（255/2047） | 非零 | NaN（Not a Number，非法运算结果） |

## 精度问题

浮点数**不能精确表示所有十进制小数**，例如 $0.1$ 在二进制中是无限循环小数：

$$0.1 = 0.0001100110011\ldots_2$$

这是浮点运算产生误差的根本原因，不是 bug，是规范本身的限制。

```python
>>> 0.1 + 0.2
0.30000000000000004   # 不等于 0.3
```

## 浮点数的加减乘除

### 加减：对阶、运算、规格化、舍入

以二进制加法 $1.10_2\times2^2+1.00_2\times2^0$，即 $6+1$ 为例：

1. **拆字段**：取出符号、真实指数、有效数；规格化数补回隐含的 `1`。
2. **对阶**：小指数向大指数对齐，右移有效数：$1.00_2\times2^0=0.01_2\times2^2$。
3. **有效数相加减**：$(1.10_2+0.01_2)\times2^2=1.11_2\times2^2$，结果为 7；异号时实际做有效数相减。
4. **规格化**：若产生进位，右移并增加指数；若相消出现前导零，左移并减小指数。
5. **舍入与编码**：按目标精度和舍入模式处理多余位，再组成 IEEE 754 编码，检查上溢、下溢等情况。

对阶时被移出的低位可能影响舍入，不能简单全扔掉；实现通常保留保护位、舍入位和粘滞位。指数相差太大时，小数的贡献可能最终被舍掉，因此 `a + b` 可能仍等于 `a`。

### 乘除：分别处理符号、指数、有效数

| 运算 | 符号         | 指数         | 有效数 | 最后处理               |
| ---- | ------------ | ------------ | ------ | ---------------------- |
| 乘法 | 两符号位异或 | 真实指数相加 | 相乘   | 规格化、舍入、重新编码 |
| 除法 | 两符号位异或 | 真实指数相减 | 相除   | 规格化、舍入、重新编码 |

这里的**有效数包含隐含的整数位 `1`**，不是仅对存储的 23 位小数做乘除。例如 $1.10_2=1+1/2=1.5$，所以 $1.10_2\times2^2=6$。

**例 1：乘法 $(-6)\times3=-18$**

先把两个数写成二进制规格化形式：

$$
-6=(-1)^1\times1.10_2\times2^2,\qquad
3=(-1)^0\times1.10_2\times2^1
$$

1. **符号异或**：$1\oplus0=1$，结果为负。同号相乘为正，异号相乘为负，除法也一样。
2. **真实指数相加**：$2+1=3$。
3. **有效数相乘**：$1.10_2\times1.10_2=10.01_2$，即 $1.5\times1.5=2.25$。
4. **规格化**：$10.01_2$ 的整数部分不止一位，将小数点左移一位；有效数缩小为原来的 $1/2$，指数就要增加 1，保持数值不变：

$$
-10.01_2\times2^3=-1.001_2\times2^4
$$

5. **舍入与编码**：$1.001_2=1.125$，因此结果为 $-1.125\times16=-18$。这个结果可被单精度精确表示，无需因截断而改变数值。符号位为 `1`，存储阶码为 $4+127=131$，小数部分存 `001` 后补零。

注意：先算出的指数 3 是**规格化之前**的指数，最终指数是 4。

**例 2：除法 $4\div6=2/3$**

$$
4=1.00_2\times2^2,\qquad6=1.10_2\times2^2
$$

1. **符号异或**：$0\oplus0=0$，结果为正。
2. **真实指数相减**：$2-2=0$。
3. **有效数相除**：$1.00_2\div1.10_2=0.101010\ldots_2$，即 $1\div1.5=2/3$。
4. **规格化**：有效数小于 1，将小数点右移一位；有效数扩大为原来的 2 倍，指数就要减小 1：

$$
0.101010\ldots_2\times2^0
=1.010101\ldots_2\times2^{-1}
$$

5. **舍入与编码**：单精度只有 23 位显式小数位，无法存完无限循环的 `01`，需根据舍入模式处理多余位。最终存储阶码为 $-1+127=126$；按常用的“就近舍入，正中取偶”，结果约为 `0.6666666865348816`，不再是精确的 $2/3$。

乘除与加减不同：**乘除不需要先对阶**，直接对有效数做乘除、对指数做加减，之后再规格化和舍入。

**为什么存储阶码在乘法中减偏置、除法中加偏置？**

令真实指数为 $e$，存储阶码为 $E=e+B$，单精度偏置 $B=127$。

乘法要求真实指数相加，再加一次偏置：

$$
E_{\text{乘}}=(e_a+e_b)+B
=(E_a-B)+(E_b-B)+B
=E_a+E_b-B
$$

两个存储阶码相加，里面已经含了两次偏置；结果只需要一次，所以要减掉一次。

除法要求真实指数相减，再加一次偏置：

$$
E_{\text{除}}=(e_a-e_b)+B
=(E_a-B)-(E_b-B)+B
=E_a-E_b+B
$$

两个存储阶码相减，偏置互相抵消了；结果仍要带偏置，所以要加回一次。

| 对照前面的例子 | 规格化前的存储阶码 | 规格化修正 | 最终存储阶码 |
| --- | --- | --- | --- |
| $(-6)\times3$ | $(2+127)+(1+127)-127=130$ | 有效数右移一位，指数加 1 | $131$，对应真实指数 4 |
| $4\div6$ | $(2+127)-(2+127)+127=127$ | 有效数左移一位，指数减 1 | $126$，对应真实指数 −1 |

上述阶码公式是**规格化及舍入修正之前**的计算；如果舍入又产生进位，还可能再次调整指数。中间指数计算必须保留足够位数，并检查范围，不能直接按 8 位阶码溢出回绕。

零、无穷、NaN、非规格化数需按相应规则另行处理。例如非规格化数的隐含整数位是 `0`；`0 × ∞` 和 `0 ÷ 0` 产生 NaN；有限非零数除以零产生带符号无穷。这些情况不能套用普通规格化数公式。
