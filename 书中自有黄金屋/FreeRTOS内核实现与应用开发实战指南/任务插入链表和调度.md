## 任务的插入

FreeRTOS 用**双向链表**管理任务。就绪任务按优先级挂到就绪链表 `pxReadyTasksLists[]` 上，调度器从链表里挑最高优先级任务运行。

```
就绪链表 List_t
  └─ xListEnd（哨兵） ⇄ xStateListItem（任务A）
                       ⇄ xStateListItem（任务B）
                              │ pvOwner 指向
                              ▼
                          TCB（任务B）
                              ├─ pxTopOfStack → 栈顶（保存的 16 个寄存器现场）
                              └─ pxStack      → 栈底（任务栈起始地址）
```

- `pvOwner` 是**从链表节点找回 TCB** 的桥梁：链表里存的是 `xStateListItem` 节点，调度器通过 `pvOwner` 拿到任务本体，再取 `pxTopOfStack` 恢复现场。
- 一个任务有**两个链表项**：`xStateListItem` 管「就绪/阻塞」状态，`xEventListItem` 管「等队列/信号量」事件，让任务能同时挂在两个链表上。
- `pxTopOfStack`（栈顶）和 `pxStack`（栈底）一高一低框出整个任务栈，切换任务时从 `pxTopOfStack` 恢复现场。

## 任务的调度

任务切换靠 **PendSV**（可挂起系统调用）中断完成。`taskYIELD()` 只把 PendSV 挂起位置位，不立即切：PendSV 优先级被设为最低，等当前所有中断处理完、CPU 空闲时才真正触发——正好在"别人都忙完"的空档切走，不打乱任何正在执行的中断。

PendSV 的中断函数是 `xPortPendSVHandler`（纯汇编），整体分「**存现场 → 选任务 → 恢复现场**」三步：

```asm
xPortPendSVHandler
    extern pxCurrentTCB       ; 当前任务 TCB 指针
    extern vTaskSwitchContext ; C 语言调度函数

    mrs r0, psp               ; ① 取当前任务栈指针 PSP（任务专用栈）
    isb

    ldr r3, =pxCurrentTCB     ; 取 pxCurrentTCB 变量的地址
    ldr r2, [r3]              ; 取它的值 = 当前 TCB 指针

    stmdb r0!, {r4-r11}       ; ② 手动把 R4-R11 压入任务栈
    str r0, [r2]              ;    新栈顶写回 TCB->pxTopOfStack

    stmdb sp!, {r3, r14}      ; 保护 R3、R14（马上调 C 函数会被破坏）
    mov r0, #configMAX_SYSCALL_INTERRUPT_PRIORITY
    msr basepri, r0           ; 屏蔽低优先级中断
    bl vTaskSwitchContext     ; ③ 选最高优先级任务，更新 pxCurrentTCB
    mov r0, #0
    msr basepri, r0           ; 开中断
    ldmia sp!, {r3, r14}      ; 恢复 R3、R14

    ldr r1, [r3]              ; 重新取 pxCurrentTCB（已指向新任务）
    ldr r0, [r1]              ; 取新任务栈顶

    ldmia r0!, {r4-r11}       ; ④ 手动弹回 R4-R11
    msr psp, r0               ;    PSP 指向新任务栈
    bx r14                    ; 异常返回，硬件自动弹异常帧
```

### 一半自动、一半手动

进入 PendSV 时，CPU 已经**自动**把 8 个寄存器压进任务栈（叫**异常帧**）：`xPSR、PC、LR(R14)、R12、R3、R2、R1、R0`——这是硬件行为，程序不用管。

剩下 `R4-R11` 硬件**不会**自动保存（AAPCS 约定它们是"被调用者保存"寄存器），必须由 handler 手动 `stmdb r0!, {r4-r11}` 压栈。

| 寄存器 | 保存方 | 时机 |
| --- | --- | --- |
| R0-R3, R12, LR, PC, xPSR | 硬件自动 | 异常进入时压栈 |
| R4-R11 | 手动 `stmdb` | handler 内压栈 |

8 自动 + 8 手动 = 16 个寄存器，凑成一个任务完整的运行现场。切换 = 把当前任务的现场存进它自己的栈，再把新任务的现场弹出来。

### 恢复现场 = 无感切换

恢复顺序相反：先手动 `ldmia r0!, {r4-r11}` 弹回 R4-R11，再 `bx r14` 异常返回，硬件自动弹出剩余 8 个寄存器——其中 **PC 被弹上的是新任务的入口/断点地址**，CPU 顺着 PC 直接跳到新任务继续跑。整个过程任务毫无感知，就是"无感切换"。
