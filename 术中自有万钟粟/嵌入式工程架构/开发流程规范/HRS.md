## 1 引言

### 1.1 目的

本文档用于定义 EC-S100 智能手表的硬件需求（HRS），确保硬件设计可支撑系统需求（SyRS）、软件需求（SSRD/SRS）及后续验证（V&V）。需求采用可度量、可验证的表达，便于评审、采购、测试与量产。

### 1.2 范围与边界

包含：MCU与存储、显示与交互、传感器与采集、供电与充电、射频与天线、接口与调试、结构与环境适应、可靠性与可制造性。

不包含：手机App与云平台需求；算法细节；生产工艺参数（另行以工艺文件/检验规范覆盖）。

### 1.3 参考文档

### 1.5 需求编号规则

硬件需求采用统一编号：HRS-<CATEGORY>-<NNN>。CATEGORY 建议：SYS（系统/通用）、MCU、BLE、DISP、INP、SENS、STRG、PWR、IF（接口）、SEC（安全）、MECH（结构）、ENV（环境）、REL（可靠性）、MFG（可制造/产测）、REG（法规）。

优先级：P0（必须/阻塞交付）、P1（重要/应具备）、P2（可选/后续版本）。验证方式：I（检查/评审）、A（分析/计算）、T（测试/实验）、D（演示/试用）。

## 2 产品与场景约束（受限网络工况）

### 2.1 应用场景摘要

面向矿井、隧道、山区、海上平台等弱网/无网环境的作业人员安全管理。手表需在离线情况下完成生命体征采集、告警、存储与本地提示；当与手机建立 BLE 连接后同步数据与位置。GPS 不在手表侧实现，由手机侧定位并经 BLE 同步。NFC 功能不纳入当前版本。

### 2.2 关键硬件设计驱动

| 驱动点 | 硬件含义 | 典型影响 |
| --- | --- | --- |
| 离线可用 | 设备侧必须具备本地计算与存储能力 | 外部 Flash 容量、写入寿命、掉电保护 |
| 低功耗长续航 | 多状态功耗可控，支持深度睡眠 | 电源架构、时钟、唤醒源、传感器占空比 |
| 强干扰与鲁棒 | 通信/电源/ESD/EMC 需强化 | UART协议可靠性、ESD防护、接地/屏蔽 |
| 可量产可测试 | 必须有产测接口与可测点 | SWD/串口/射频测试、治具接触点、ICT/功能测试 |

## 3 硬件总体方案（概述）

### 3.1 双MCU分工

STM32F411 负责 UI/传感器/存储/低功耗；nRF52840 负责 BLE 连接与手机交互。两者通过 UART 进行协议化通信（ACK/超时重传/CRC）。该方案降低射频复杂度与主控负担，同时便于后续 BLE 能力升级。

### 3.2 关键器件与外设清单（最小配置）

| 子系统 | 建议器件/接口 | 备注 |
| --- | --- | --- |
| 主控MCU | STM32F411CEU6 | Cortex-M4F |
| BLE协处理 | nRF52840 | BLE 5.x/mesh 预留 |
| 外部Flash | W25Q64（8MB） | OTA缓存/日志/数据 |
| 显示 | 240x240 TFT（ST7789或同级）+ SPI | 背光PWM控制 |
| 输入 | 触摸屏/按键（至少1个物理按键） | 用于唤醒/确认 |
| 传感器 | AHT21（温湿度）、MPU6050（IMU）、PPG（HR/SpO2，可选） | 根据版本裁剪 |
| 音/振动 | 蜂鸣器或喇叭 + 振动马达（可选） | 用于告警提示 |
| 电源 | 锂电池 + 充电管理 + 电量采样 | 支持低电策略 |
| 调试/产测 | SWD（STM32）、SWD或SWDIO（nRF）、UART测试点 | 量产与返修 |
