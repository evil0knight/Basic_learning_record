# BRD 书写推理依据

> 提炼自 `BRD会议记录文字.md`(内部培训会议口头记录)。本文档是写作时的**推理依据**:用于理解每一节"为什么写、如何从需求推导"。模板结构见 `brd-template.md`,两者配合使用。

## 总纲

- BRD 是研发人员在 PDP 流程第六章、立项结束后书写的**第一个文档**。
- 它要完成三件事:获取公司需求 → 分析/拆解/建模 → 确定优先级与验证方法。
- 全文回答一个核心问题:**谁来买、谁付费、谁会去用**。
- 一个项目可能含多个产品,每个产品单独成一份 BRD;文档首行写"项目名 + 具体产品 + 时间"。

## 各节推理要点

### 1. 文档控制与审批记录
- 首行无实质内容,记录项目名与时间即可。
- 体现它是受控文档:谁批准、版本号、权威入口。

### 2. 执行摘要与立项结论
- 写**为什么立项**,承接前几章输入(商业章程、商业案例、约束、立项标准)。
- 推导逻辑:需求方确实需要 + 有足够规模支撑 → 立项成立。
- 例:学员需要这块板子、为方便学习开发、且学员规模足够支撑使用 → 立项。

### 3. 业务背景、问题与机会
- 写产品所处的使用背景与约束(如体积要求不高,但功能要完善)。
- 逐条列功能诉求(电源防护、低功耗测试、测试点位多、SPI/I2C 引出、标识清晰)。
- 由背景推导出"问题"与"机会"。

### 4. 目标客户、使用方与干系人
- 核心动作:**拆解谁买、谁用**,并按角色分别写"关注什么结果"。
- 不同角色关注点不同,必须分别写清。示例(开发板):
  - 科研人员 → 关注能否准确测血氧、是否有实验台与蓝牙网关。
  - 教育培训机构 → 关注电源防 ESD、IO 全引出、急停开关、LED 区域标识。
  - 快速原型公司 → 关注高性价比、规格明确、能快速让软件跑起来、可做故障测试。

### 5. 业务目标与预期业务成果
- 把内部需求搞明白后,落到**时间点 + 可交付物**。
- 例:8/30 第一版功能样机(可跑 LVGL)→ 9/10 工程样机(接近可生产)→ 9/30 生产 200 片。
- 业务目标须与立项时定下的需求一致。

### 6. 价值主张与差异化假设
- 价值主张要有**证据支撑**(如问卷调研数据支撑项目开发)。
- 差异化要具体可列:例如 IO 口多、可引出设备,而别家开发测试板无此功能。

### 7. P0 业务范围与明确非目标
- 项目通常很大、不能一次做完 → 先定 P0 完成哪些,再 P1,其余为非目标。

### 8. 业务需求与成功指标
- 把 P0 拆解到具体目标,并给出**可验收的成功指标**。
- 例:8/30 出第一版样机,且血氧测试满足某标准。

### 9. 约束、假设和外部依赖
- 列关键依赖:人员是否够、资金是否够、关键器件(如传感器)是否有货。

### 10. 里程碑、投入边界和决策闸门
- 设计划窗口:某日期能否拿出首个里程碑。
- 拿不出则客户可能判定项目不行 → 触发"不再继续投入"的闸门决策。

### 11. 主要风险、应对与退出条件
- 风险 + 应对 + 退出条件。例:
  - 血氧不稳定 → 持续调试。
  - 代码架构混乱 → 直接退出、停做项目。

### 12. 治理、Owner 和变更批准机制
- 需求要**分配到人**(每人负责哪个需求),明确 Owner 与治理边界。

### 13. BRD 到 PRD 追溯矩阵
- 前面所有目标/需求最终都要能**映射到 PRD**;PRD 可反查由哪个 BRD 支撑。

### 14. 待验证商业假设与后续调研
- 写不确定、需 POC 验证的东西。
- 例:血氧能否测到某精度?不确定 → 记为假设,开发过程再确认。

### 15. 历史基线与版本记录
- 记录各版本"为什么改",做修改留痕。
