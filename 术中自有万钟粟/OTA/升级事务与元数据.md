# 升级事务与元数据

## 模块功能

- **输入：** 升级请求、各模块结果、持久化记录、复位后的恢复事件。
- **处理：** 控制升级阶段，检查进入条件，持久化关键进展，决定继续、终止或恢复。
- **输出：** 下一阶段命令、可启动镜像选择、成功或失败事件。

## 基础事务状态

以下是状态语义，不规定代码中的枚举名称或固定任务数量。

| 阶段 | 进入条件 | 允许产生的结果 |
| --- | --- | --- |
| 空闲 | 无活动会话 | 接受新请求 |
| 接收中 | 能力与目标区域检查通过 | 接收完成，或丢弃本次候选 |
| 候选就绪 | 数据持久化且规定的验证通过 | 等待安装授权；不能仅凭接收完成进入 |
| 安装中 | 获得安装授权，策略的恢复前提满足 | 安装成功，或按策略恢复 |
| 已提交 | 启动目标完整有效，启动选择持久化 | 请求复位或启动交接 |
| 恢复中 | 发现未完成事务或失败安装 | 回到可启动版本或恢复下载 |

下载授权与安装授权属于外部策略。候选就绪不等于安装已授权，用户取消安装也不应偷偷写入“下次启动安装”的标志。

## 持久化元数据

元数据记录格式版本、记录序号、会话与镜像标识、阶段、目标区域、有效长度、验证信息及策略所需的恢复信息。A/B、试运行次数等是策略扩展，不强迫所有产品保存这些字段。

反码或 CRC 可以帮助发现记录损坏，却不能保证多字段更新的原子性。可采用两份位于独立擦除单元的记录或追加日志：先写内容，再写提交标记，上电从格式、校验及提交状态都有效的记录中选择最新一份。

记录写入、提交标记和旧记录回收须符合存储器编程粒度及擦除行为。没有有效记录时只能按恢复策略处理，不能推断某个候选“应该已安装”。

## 掉电恢复约束

- 先完成数据写入和验证，再记录候选就绪；记录不能跑在数据前面。
- 在破坏旧镜像前，先满足安装策略要求的备份或恢复前提。
- 安装进度要么可持久化恢复，要么可安全从头重做；重入不能擦掉唯一恢复来源。
- 只有安装结果验证成功后才提交新的启动选择。

事务协调是必需能力，跨复位升级需要持久化记录；具体存储介质可替换。它不等于 A/B 状态机，也不应直接操作某颗 EEPROM 或 Flash。
