# 板子上的 BOOT0 和 BOOT1

---

## 一、物理属性与基本概念

- **硬件引脚/按键**：板子上的 boot0和boot1是控制引脚电平的硬件开关（通过上拉/下拉电阻接 3.3V 或 GND）
- **核心作用**：在芯片上电/复位的第一微秒，决定 CPU 从哪个物理存储区域读取第一行代码

---

## 二、BOOT0 / BOOT1 三种启动模式

| BOOT0 | BOOT1 | 启动源                     | 核心作用与场景                                          |
| ----- | ----- | -------------------------- | ------------------------------------------------------- |
| 0     | X     | 主 Flash (Main Flash)      | 正常运行模式。运行 Flash 里的 Bootloader 或 APP         |
| 1     | 0     | 系统存储器 (System Memory) | 串口救砖模式。运行 ROM 中出厂固化的官方 Bootloader      |
| 1     | 1     | 内置 SRAM                  | 内存调试模式。代码直接在 RAM 运行，断电清空，不写 Flash |

---

## 三、串口"救砖"工作原理（BOOT0 = 1, BOOT1 = 0）

**1. 为什么坏代码 / JTAG 失效也能救？**

当 APP 出现死循环、禁用 JTAG/SWD 引脚或进入深度休眠导致芯片"变砖"时，仿真器无法连接。按住 BOOT0 按键并触发 RESET 重启，硬件强制 CPU 直接绕过 Flash，坏代码完全没有机会执行。

**2. 救援执行过程**

CPU 跳转到 ROM 区域运行出厂固化的官方 Bootloader（物理只读，不可损坏），然后坏代码是不会被运行的，这时候直接烧录代码就行了。电脑通过串口发送擦除指令并重新写入新程序。
