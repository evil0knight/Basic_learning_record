## 栈模型（Cortex-M 的"满递减栈"）

**Full-Descending（满减栈）**：

**满**：栈指针 SP 永远指向有数据的栈地址。你不先移动指针就开始向栈里写数据，就会把之前的栈数据破坏掉

**减**：SP 指针向地址变小的方向移动，比如从 `0x20001234` → `0x20001230`。对应的是**增**——地址由小到大移动（`0x20001230` → `0x20001234`）

---

## 栈的两个指针

整个函数调用栈由两根指针管理

看[cpu通用寄存器组](cpu通用寄存器组.md)里R7(栈底)和R13(栈顶)

每次函数调用，CPU 先在栈顶开辟一块新空间——**栈帧（Stack Frame）**，BP 指向栈帧底部，SP 随压栈向低地址增长

---

## 嵌套调用

上层函数的整个栈帧已经压在栈里不动了，下层函数继续从当前 SP 位置向低地址压自己的栈帧。函数返回时，栈帧弹出，SP 回退到调用前的位置，上层函数继续执行

#### 压栈:

- 如果是非叶子函数:把函数下一条指令保存到R14(看[cpu通用寄存器组](cpu通用寄存器组.md)的R14)
- 如果开启BP相对寻址:保存R7(栈底指针位置)
- 需要保存的寄存器（按需要保存R4、R5、R6）

#### 出栈:

* 如果是非叶子函数 ：将栈中保存的地址直接弹出给 **PC(R15)** 自动跳转返回；叶子函数使用 **`BX LR`** 返回
* 如果开启了 FP 相对寻址：弹出并恢复  **R7** （还原上一个函数的栈底指针位置）
* 恢复保存的寄存器 ：按需对应弹出恢复 **R4、R5、R6** 等
* 栈空间回收 ：恢复  **SP** （栈顶指针位置）

## 局部变量的访问：编译期就算好了偏移

函数内部的每个局部变量都会被压到栈里。

**在编译时期**就算好了每个变量距离 BP 的偏移量

```c
void foo(void) {
    //高地址
    int a = 1;	//BP - 4
    int b = 2;	//BP - 8
    int c = 3;	//BP - 12
    //低地址 ->sp
}
```

R7 就是 ARM Cortex-M 上的帧指针（相当于 x86 的 BP）。编译器在函数入口建栈帧时把 SP 赋给 R7，此后 R7 在整个函数执行期间不变，所有变量通过 `[R7, #偏移]` 寻址。
